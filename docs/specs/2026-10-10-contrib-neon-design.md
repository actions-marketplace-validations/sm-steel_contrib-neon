# contrib-neon design (2026-10-10)

## Context
The profile README (`sm-steel/sm-steel`) shows `Platane/snk@v3`'s snake, generated by `.github/workflows/snake.yml`, pushed to the `output` branch by `crazy-max/ghaction-github-pages@v4`, and embedded in `README.md:51-55` through a light/dark `<picture>`. The user wants their own animation instead: the same contribution-square grid, styled as cyberpunk neon, with glow that gets stronger as contribution count goes up. It should live in a **separate public repo, `sm-steel/contrib-neon`**, that anyone can reuse the way snk is reused (a GitHub Action, plus an npm CLI).

Decisions made so far:
- **Motion:** "boot + pulse". A CRT power-on sweep, then a neon breathing pulse, with glitch flickers and a scanline on top.
- **Palette:** Catppuccin. Profile uses **Latte (light) + Mocha (dark)**. All 4 flavors ship as presets, and custom hex colors are allowed.
- **Profile:** replace the snake only **after** the user approves the local preview.
- **Process:** preview locally first. The user discusses tweaks before anything is published.

Research: snk ships as an action with `outputs:` lines that take query-string options, plus `npx generate-snake-animation`. Publishing is left to the user's workflow (a push to an `output` branch). Common cyberpunk visual vocabulary: neon glow on near-black, scanlines/CRT, chromatic aberration (RGB split) glitches, HUD/telemetry text. Sources: [Platane/snk](https://github.com/Platane/snk), [daisyUI cyberpunk trend](https://trends.daisyui.com/trend/cyberpunk/), [glitch-art trend](https://trends.daisyui.com/trend/glitch-art/), [pacman-contribution-graph](https://github.com/pencilrebel/pacman-contribution-graph) (a similar reusable action).

## Design

### Visual spec (one self-contained animated SVG, no JS: GitHub's camo `<img>` allows CSS animations and SVG filters only)
- **Grid:** 53×7 cells, 11px squares, 3px gap, 2px radius (GitHub geometry), on a rounded panel. Panel color is Catppuccin `crust` for dark and `base` for light.
- **HUD strip** (optional, on by default): a small monospace header such as `// CONTRIB.LOG · sm-steel · 1,234 in the last year` and corner bracket marks. It uses a system monospace stack, because `<img>` SVGs can't load webfonts.
- **Levels** come from the GraphQL `contributionLevel` (NONE…FOURTH_QUARTILE → 0–4):
  - Mocha: L0 `surface0` #313244 (no glow) → L1 `blue` #89b4fa → L2 `lavender` #b4befe → L3 `mauve` #cba6f7 → L4 `pink` #f5c2e7. L4 also gets a near-white core.
  - Latte: #ccd0da → #1e66f5 → #7287fd → #8839ef → #ea76cb. The glow is weaker, closer to "lit ink".
  - The same ramp is used for frappé and macchiato.
- **Glow:** one `feGaussianBlur`+merge filter **per level** (5 filters total), applied to per-level `<g>` groups rather than per cell, to keep SVG size and render cost down. Blur radius and glow opacity both grow with level.
- **Animation timeline** (CSS `@keyframes`):
  1. *Boot* (~1.6s, runs once): columns light left→right with a stagger delay. Each cell does a CRT flicker-on (0 → 1 → 0.3 → 1).
  2. *Pulse* (infinite): each level group breathes, changing glow opacity and blur. Higher levels pulse brighter and faster (L1 ≈ 4s, L4 ≈ 1.6s). L0 stays static.
  3. *Scanline:* a faint band sweeps top→bottom every ~6s, over a static low-opacity line pattern.
  4. *Glitch:* about every 7s, 2–3 rows jitter horizontally for ~120ms, with offset red/cyan (Catppuccin `red`/`sky`) copies for chromatic aberration. Which rows glitch is chosen by a seeded PRNG keyed on the username, so output is deterministic.
- `prefers-reduced-motion` media query: animations are disabled and glow is static.
- Size budget: < 150 KB per SVG.

### Repo `sm-steel/contrib-neon` (new, public)
```
contrib-neon/
  mise.toml                 # node (LTS) pinned
  package.json              # bin: contrib-neon; deps: none at runtime (fetch is built in)
  tsconfig.json, biome.json
  src/
    fetch.ts                # GraphQL contributionsCollection.contributionCalendar → Day[] {date,count,level}
    palette.ts              # catppuccin flavors (latte/frappe/macchiato/mocha) + custom override parsing
    options.ts              # parse "file.svg?flavor=mocha&hud=false&color_levels=..." (snk-style)
    render/
      grid.ts               # layout math (week columns, coords)
      filters.ts            # per-level glow filter defs
      animation.ts          # CSS keyframes: boot / pulse / scanline / glitch (seeded)
      svg.ts                # assemble final SVG string
    cli.ts                  # contrib-neon --user X --out a.svg?flavor=mocha [--fixture f.json]
    action.ts               # reads inputs, calls the same pipeline
  action.yml                # runs: node24, main: dist/action.js (bundled with esbuild, committed)
  fixtures/                 # sample calendars (empty / sparse / busy) for offline preview + tests
  preview/index.html        # generated: Latte & Mocha side by side, on GitHub light/dark backgrounds
  test/                     # vitest: options parsing, level mapping, layout, deterministic SVG snapshot
  docs/specs/2026-10-10-contrib-neon-design.md   # this design, written as the spec
  README.md                 # usage workflow example, options table, preview GIF
  .github/workflows/ci.yml  # mise install → lint → test → verify dist/ is up to date
```
- **Action usage**, modeled on snk:
  ```yaml
  - uses: sm-steel/contrib-neon@v1
    with:
      github_user_name: ${{ github.repository_owner }}
      outputs: |
        dist/neon.svg?flavor=latte
        dist/neon-dark.svg?flavor=mocha
  - uses: crazy-max/ghaction-github-pages@v4
    with: { target_branch: output, build_dir: dist }
    env: { GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} }
  ```
  `github_token` defaults to `${{ github.token }}` (enough for public contribution data).
- **npm:** published later as `contrib-neon`, after the user decides, which enables `npx contrib-neon`. It is not part of the first iteration.
- Tooling: TypeScript, Biome, Vitest, esbuild, all pinned via mise/package.json. Commit email comes from the default global git config.

### Data flow
`fetch(user, token)` → `Day[]` → `resolveOptions(outputLine)` → `renderSvg(days, palette, opts)` → write file. The CLI with `--fixture` skips the fetch, so previews and tests work offline.
